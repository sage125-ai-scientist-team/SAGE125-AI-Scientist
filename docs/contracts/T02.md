# T02 Reviewer 修订与版本契约

本文件是 T02 Wave A 生产契约的权威说明。实现位于
`app/contracts/revision.py`，工作流接入位于 `app/workflow/pipeline.py`。
契约不修改公共 `PipelineState` 或 `ReviewResult` Schema，也不改写
T01/T03/T05/T06 的内部实现。

## 1. 状态对象

`ReviewFeedback` 是 `ReviewResult` 的可序列化快照，完整保留：

- `passed`
- `critical_issues`
- `required_revisions`
- `reviewer_comments`
- `risk_level`
- 四项评审分数

有效通过必须同时满足：

```text
passed is True
critical_issues == []
required_revisions == []
```

`RevisionContext` 保存 `run_id`、权威 `revision_iteration`、上一轮
`ReviewFeedback` 和 `IssueClosure`。第一轮的 `revision_iteration=1`，第二轮为
`2`；第二轮 Prompt Builder 缺少上一轮反馈时拒绝构造输入。

`IssueClosure` 使用稳定 `issue_id`、问题类型、说明、开启版本、状态、关闭版本和解决
说明。稳定 ID 由问题类型和规范化说明的 SHA-256 派生，不使用随机数、UUID 或时间戳。
未解决问题保持 `open`；只有带有效 `closed_in_version` 的记录才能标记为
`resolved`。

## 2. Prompt Builder

`RevisionPromptBuilder` 为 HypothesisGenerator、ExperimentDesigner 和
ScientificReviewer 构造确定性输入。

- 第一轮输入包含 `revision_iteration=1`，不伪造历史反馈。
- 第二轮输入包含 `revision_iteration=2` 和上一轮完整 `review_result`。
- HypothesisGenerator 与 ExperimentDesigner 收到同一份反馈，不猜测性拆分意见。
- ExperimentDesigner 的最终 user 消息继续包含 `revision_iteration` 和完整
  `review_result`。
- `fingerprint()` 对完整规范化输入计算 SHA-256，不依赖生产端 600 字符摘要。

## 3. PlanVersion 与版本存储

`PlanVersion` 保存：

- `run_id`、`version_number`、确定性 `version_id`
- `parent_version_id` 与 `revision_iteration`
- 完整假设、实验、Reviewer 反馈及 IssueClosure 快照
- 各 Agent 的完整输入指纹

版本 ID 固定为 `<run_id>:v<version_number>`。V1 不得有父版本；V2 及之后必须引用
前一版本。`PlanVersionStore` 只接受连续版本，支持：

- `save()` 保存下一版本；
- `get()` / `list_versions()` 读取防御性副本；
- `serialize()` / `deserialize()` 保存和恢复完整 store。

该最小 store 不引入数据库或跨任务存储重构；序列化结果可由现有 artifact/持久化适配
层保存。

## 4. 兼容迁移与序列化

`RevisionState` 聚合 `RevisionContext`、有序 `PlanVersion` 和终态。
`serialize_revision_state()` 与 `deserialize_revision_state()` 提供稳定 JSON 往返。

`migrate_revision_state_payload()` 兼容缺少新字段的旧快照：

- 缺少 `schema_version` 时视为旧格式；
- `iteration` 迁移为 `revision_iteration`；
- `review_result` 迁移为 `review_feedback`；
- `plan_versions[*].version` 迁移为 `version_number`；
- 缺失 issue、版本或评审字段使用保守默认值；
- 缺失终态时默认为 `draft`；
- 未来未知 schema version 明确拒绝，避免静默误读。

往返后必须保留 Reviewer 三个反馈字段、`revision_iteration`、版本编号、父子 lineage、
issue 状态与 prompt 指纹。

## 5. 终态与最大轮次

当前工作流最多两轮。Reviewer 首轮未有效通过时，在启用自动修订且尚未修订的条件下
进入第二轮。第二轮仍存在以下任一情况时，终态不得为
`ready_for_validation` 或 `validated`：

```text
passed is not True
critical_issues 非空
required_revisions 非空
任一 IssueClosure.status == "open"
```

工作流和 `RevisionState` 均执行该防御性规则。阻断反馈与问题必须保留，不得仅因
`revision_history` 增长视为成功修订。

现有公共 Schema 没有 `stop_reason`，本契约不擅自扩展公共接口。达到两轮上限后通过
阻断反馈、开放 IssueClosure 和 `draft` 终态表达未解决状态。
