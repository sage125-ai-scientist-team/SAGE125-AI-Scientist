# T01 Evidence Contract v2

## Purpose

This document defines the evidence contract used by downstream scientific agents.

The goal is to ensure every factual claim can be traced to real scientific evidence.

---

# 1. EvidenceCardV2

EvidenceCardV2 represents a traceable scientific evidence unit.

Required information:

- evidence_id

- source_id

- source_type

- title

- quoted_text

- locator

- authors

- year

- DOI/URL

- content_hash

- verification_status

Design principles:

1. Title or metadata alone cannot support established facts.

2. Evidence must preserve original text and location information.

3. Unverified evidence must remain pending.

---

# 2. ClaimEvidenceLink

ClaimEvidenceLink connects factual claims with EvidenceCards.

Fields:

- claim_id

- evidence_id

- relation

- confidence

- validation_status

Supported relations:

- supports

- contradicts

- context

Validation rules:

- evidence_id must correspond to an existing EvidenceCard.

- unsupported claims cannot enter established facts.

---

# 3. EvidenceBundle

EvidenceBundle provides controlled evidence context for downstream agents.

Contains:

- EvidenceCardV2 list

- ClaimEvidenceLink list

- token budget

- truncation status

- truncation reason

Purpose:

Avoid uncontrolled full-document injection while preserving evidence traceability.

---

# 4. Red-light Test Requirements

The following cases must fail:

## Invalid evidence_id

A claim references an unavailable evidence_id.

Expected:

Reject or mark pending verification.

## Title-only evidence

Evidence contains only title or metadata without verified quotation.

Expected:

Cannot support established facts.

## booklet_excerpt as evidence

Question booklet content is used as scientific evidence.

Expected:

Reject.

## Cross-domain extrapolation

Evidence from one domain is directly used to support unrelated conclusions.

Expected:

Require additional validation.

---

# 5. Migration Strategy

The existing EvidenceCard remains compatible.

EvidenceCardV2 is introduced as a contract layer.

Runtime workflow integration is handled by downstream tasks after contract review.
