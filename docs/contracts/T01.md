# T01 Evidence Contract (EvidenceCardContract)

## Purpose

This document freezes the Wave A evidence contract used by downstream scientific agents.

Implementation source of truth: `app/contracts/evidence.py`

Canonical type name: **EvidenceCardContract** (not EvidenceCardV2).

The goal is to ensure every factual claim can be traced to real scientific evidence.

---

# 1. EvidenceCardContract

`EvidenceCardContract` represents a traceable scientific evidence unit.

Required fields:

- evidence_id
- source_id
- source_type
- title
- quoted_text
- locator
- authors (default empty list)
- year (optional)
- doi / url (optional)
- content_hash (optional for pending; **required when verification_status=valid**)
- domain (optional; used for cross-domain supports checks)
- verification_status (`valid` | `invalid` | `pending` | `rejected`, default `pending`)

Allowed `source_type` values:

- paper
- dataset
- experiment
- web
- contract
- specification
- test_fixture
- question_booklet

Design principles / validators:

1. Title or metadata alone cannot support established facts.
   - If `quoted_text.strip().lower() == title.strip().lower()`, `verification_status=valid` is rejected.
   - Wave B support checker also **BLOCK**s DOI-only / URL-only quotes as `METADATA_ONLY`
     (e.g. `quoted_text='10.1234/x.y.z'`), even when title differs.
2. Evidence must preserve original text and non-empty locator.
3. Unverified evidence must remain pending.
4. Question booklet sources (`source_type=question_booklet`, `source_id` containing `booklet`, or `locator.source=booklet`) cannot be `valid`.
5. Missing `content_hash` forbids `verification_status=valid` (Wave A policy).

---

# 2. ClaimEvidenceLink

`ClaimEvidenceLink` connects factual claims with `EvidenceCardContract` objects.

Fields:

- claim_id
- evidence_id
- relation (`supports` | `contradicts` | `context`)
- confidence (`0.0`–`1.0`)
- claim_domain (optional)
- validation_status (`valid` | `invalid` | `pending`)

Validation rules:

- `evidence_id` must correspond to an existing card inside the same `EvidenceBundle`.
- Unsupported / unknown references are rejected at Bundle construction time.
- `supports` with both `claim_domain` and evidence `domain` set but unequal is rejected (cross-domain red light).

---

# 3. EvidenceBundle

`EvidenceBundle` provides controlled evidence context for downstream agents.

Contains:

- EvidenceCardContract list (`evidences`, non-empty, unique evidence_id)
- ClaimEvidenceLink list (`links`, non-empty)
- token_budget (default 8000)
- truncated
- truncation_reason

Bundle construction enforces:

1. Every `link.evidence_id ∈ evidences.evidence_id`
2. Cross-domain `supports` rejection when domains disagree
3. Token budget / truncation metadata for later controlled injection

Purpose:

Avoid uncontrolled full-document injection while preserving evidence traceability.

# 4. Red-light Test Requirements

Implemented in `tests/evidence/test_evidence_contract.py`.

## Invalid evidence_id

A claim references an unavailable evidence_id.

Expected:

Reject at Bundle construction (`ValidationError`) and via `validate_evidence_link`.

## Title-only evidence

Evidence contains only title/metadata without distinct quotation.

Expected:

Default remains `pending`; `verification_status=valid` is rejected.

## booklet_excerpt as evidence

Question booklet content is used as scientific evidence.

Expected:

Cannot be `valid`; rejected when forced to `valid`.

## Cross-domain extrapolation

Evidence from one domain is used to `supports` an unrelated claim domain.

Expected:

Bundle construction rejects the link.

# 6. Wave B Citation / T08 API Contract

## 6.1 CitationItem fields

| Field | Type | Description |
|---|---|---|
| claim_id | string | Claim identifier |
| evidence_id | string | Evidence anchor id |
| title | string | Source title |
| source_url | string\|null | Clickable DOI/URL (`https://doi.org/...` when DOI present) |
| locator | object | Must include page/section when available |
| quoted_text | string | Original quote (never dropped) |
| support_status | `allow`\|`degrade`\|`block`\|`pending` | From support checker |
| support_note | string | Optional degrade/block reason |

## 6.2 T08CitationPayload (`schema_version=t01-citation-payload-v1`)

```json
{
  "schema_version": "t01-citation-payload-v1",
  "upstream_ref": "integration/2026-08-10 + t01/b-evidence-core",
  "citations": [ { "...CitationItem..." } ],
  "markdown": "## Citations\\n..."
}
```

Python entrypoints:

- `build_citation_item(...)`
- `render_citation_markdown(citations)`
- `build_t08_citation_payload(citations, upstream_ref=...) -> T08CitationPayload`
- `T08CitationPayload.to_dict()` for JSON export

Markdown must allow claim → evidence jump via `#evidence-<id>` anchors, and include locator, quote, source link, and support status.

## 6.4 T01↔T02/T03 integration bridge (08/03 freeze)
