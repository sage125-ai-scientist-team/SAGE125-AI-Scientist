# 5. EvidenceCard Generation Audit

## 5.1 RAG Evidence Generation

Location:

```

app/rag/[evidence.py](http://evidence.py)

```

Finding:

EvidenceCard generation currently constructs quoted_text using fallback logic:

```

abstract

   ↓

summary

   ↓

title

```

Observed behavior:

When higher-quality text evidence is unavailable, metadata-level fields may become quoted_text fallback.

Potential risk:

A title or metadata field could be interpreted downstream as evidence text.

T01 concern:

EvidenceCard should distinguish:

- verified original text evidence

- metadata information

- incomplete references

# 6. Evidence ID Validation Audit

## Current Evidence ID Flow

Evidence IDs are propagated through multiple modules:

### app/agents/[base.py](http://base.py)

Responsible for collecting:

- evidence_ids

- reference_ids

- supporting_evidence_ids

### app/agents/evidence_[extractor.py](http://extractor.py)

Responsible for extracting and propagating evidence_ids.

### app/agents/hypothesis_[generator.py](http://generator.py)

Carries evidence_ids into hypothesis generation.

### app/agents/report_[writer.py](http://writer.py)

Collects evidence_ids for final output.

---

## Current Constraints

The current system applies several constraints:

- factual claims should reference EvidenceCard evidence_id;

- unsupported content should remain knowledge gaps or pending hypotheses;

- DeepResearch summaries should not directly become validated facts.

These constraints mainly rely on:

1. Prompt-level requirements.

2. Schema-level validation.

3. Evidence ID propagation.

---

## Validation Finding

During baseline repository audit, no explicit deterministic validation logic was identified that verifies:

```

evidence_id ∈ available EvidenceCards

```

Current finding:

The system contains evidence ID generation and propagation mechanisms, but the existence relationship between claims and actual EvidenceCard objects requires further validation.

Potential risk:

A generated claim may contain:

- unavailable evidence_id;

- incorrectly assigned evidence_id;

- unsupported evidence reference.

Recommended future direction:

Add deterministic evidence grounding validation before allowing claims to enter established facts or validated outputs.
