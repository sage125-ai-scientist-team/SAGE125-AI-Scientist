# 4. EvidenceCard Generation Audit



## 4.1 RAG Evidence Generation

Location:

```

app/rag/[evidence.py](http://evidence.py)

```

Observed behavior:

EvidenceCard generation uses fallback logic:

```

abstract

   ↓

summary

   ↓

title

```

to construct:

```

quoted_text

```

Finding:

When higher-quality text evidence is unavailable,

metadata-level fields may become quoted_text fallback.

Potential risk:

A title or metadata field may be interpreted downstream as evidence content.

Required future improvement:

EvidenceCard should distinguish:

- verified source quotation;
- metadata information;
- insufficient evidence.

# 12. Evidence Catalog Boundary Audit

## Target

The baseline audit inspected the evidence catalog generation boundary that feeds
downstream scientific agents.

Audited call path:

```text
app/workflow/pipeline.py
  -> _evidence_catalog(evidence_pool, limit=30)
  -> Agent input["evidence_catalog"]
  -> EvidenceExtractor / HypothesisGenerator / ExperimentDesigner / ScientificReviewer
```

Purpose: verify whether evidence provenance (especially `quoted_text`) is preserved
before evidence objects are consumed by downstream reasoning components.

## Keep / Drop Field Table (runtime catalog)

Source of truth: `app/workflow/pipeline.py:217-226` (fields appended into each catalog dict).

### Kept by `_evidence_catalog`

| Field | Status |
|---|---|
| `id` | kept |
| `title` | kept |
| `source_type` | kept |
| `doi` | kept |
| `url` | kept |
| `year` | kept |
| `relevance_score` | kept |

### Dropped / never included in catalog

| Field | Status | Risk |
|---|---|---|
| `quoted_text` | **dropped** | Agents see title/DOI metadata without original quotation |
| `summary` | **dropped** | Abstract/summary context unavailable in catalog |
| `authors` | **dropped** | Authorship provenance unavailable in catalog |
| `reliability_note` | **dropped** | Source-path / page / rerank notes unavailable in catalog |
| `locator` | not present on runtime `EvidenceCard`; not added by catalog | No page/section locator in Agent catalog input |
| `source_id` | not present on runtime `EvidenceCard`; not added by catalog | Contract-layer `source_id` not propagated here |
| `verification_status` | not present on runtime `EvidenceCard`; not added by catalog | Contract-layer verification gate not applied at catalog boundary |
| `content_hash` | not present on runtime `EvidenceCard`; not added by catalog | Hash provenance not available to Agents via catalog |

## Findings

1. Quote preservation: catalog intentionally omits `quoted_text` (docstring + code).
2. Metadata-only exposure: Agents primarily receive `title` / `doi` / `url` / `year`.
3. Provenance validation: catalog does not enforce `verification_status`, locator, or hash.
4. Contract gap: `EvidenceCardContract` in this PR defines the required fields, but runtime
   `_evidence_catalog` is not yet integrated with that contract (deferred to later waves / T02).

Observed boundary behavior:

- Evidence **identity** (`id`) and metadata (`title`, `doi`, `url`, `year`, `source_type`, `relevance_score`) are propagated.
- Evidence **quotation / summary / authors / reliability_note** are dropped at the catalog boundary.
- Downstream Agents that only receive `evidence_catalog` therefore cannot ground claims on original text from this path alone.

## Conclusion

The audit confirms that `_evidence_catalog` preserves evidence identity and lightweight metadata,
but drops provenance-critical text fields—especially `quoted_text`.

The `EvidenceCardContract` and validation tests introduced in this PR provide the contract-level
protection layer. Runtime pipeline integration at the catalog boundary remains a future step
and is intentionally out of scope for T01-A (no unauthorized `pipeline.py` rewrite in this PR).
