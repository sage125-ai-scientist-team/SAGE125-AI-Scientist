Static risks requiring future executable validation
----------------------------------------------------

1. Stable Mock evidence IDs are global across questions

   Evidence: `app/workflow/mock_outputs.py:27-28,311-314` uses
   `EV-MOCK-0001..0003` for every selected question.

   Risk: any future cross-run evidence cache or global dedup keyed only by evidence ID can merge
   unrelated questions. The current per-run state limits this risk, but no batch-level cache
   namespace contract proves safety.

2. AI topic matching uses substring `"ai"`

   Evidence: `app/workflow/mock_outputs.py:267` includes `"ai"` and lines 283-286 use substring
   containment.

   Risk: a non-AI question/domain containing the letters `ai` inside another word can select the AI
   Mock content pack. This is a static risk only; no authoritative question catalog is available
   to bind it to a real question_id.

3. Resume accepts stale/mismatched report.json

   Evidence: `scripts/run_batch_125.py:130-137` checks only file existence and parses it, then marks
   the row completed.

   Risk: reusing an output directory across source/prompt/model/schema changes can attach a stale
   report to the current question. No input_hash/question_id/version comparison is performed.
   No existing output is available to demonstrate the failure.
