Resume correctness risks
------------------------

At `scripts/run_batch_125.py:130-137`, resume treats the presence of
`<output-dir>/<question_id>/report.json` as completed. It does not verify:

- report.question_id equals the directory/current input question
- input hash or source version
- prompt/model/schema version
- Mock versus real mode
- PDF/MD/JSON/evidence_cards/agent_trace completeness
- T01/T03 gate results
- failed/stale/partial state

Missing-file completion risk
----------------------------

At lines 140-145 the runner copies four files only when each exists, then unconditionally appends
a row with `status="completed"`. It does not copy or inspect the per-run
`artifacts_manifest.json`, and it does not require PDF. Therefore a missing required output can
still be represented as completed in the future batch summary.

Checkpoint/crash behavior
-------------------------

Rows and the batch manifest are written only after the loop (`scripts/run_batch_125.py:161-178`).
A process crash before that point loses the in-memory rows and provides no serialized per-job
checkpoint. Per-run artifacts may survive under `exports/{run_id}`, but the batch has no durable
mapping to recover them.

Per-run artifact manifest is not the batch manifest
---------------------------------------------------

`app/workflow/artifacts.py:186-223` writes `artifacts_manifest.json` with run_id, question_id,
mode, files, missing_files, and warnings. This is useful single-run evidence, but the current
batch script neither copies nor validates it and it contains none of the required batch-level
checkpoint/version/hash fields.
