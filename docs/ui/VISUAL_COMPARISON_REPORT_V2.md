## 三之一、全局硬指标复核中发现并修复的问题：Emoji 残留

本轮在核对第十一章全局硬指标 `EMOJI_UI_COUNT=0` 时，对 `app/ui/*.py` 做了正则扫描
（`[\U0001F300-\U0001FAFF\u2600-\u27BF]`，排除箭头等纯排版符号），发现：

- 修改前：`components.py` 34 处、`errors.py` 3 处、`streamlit_app_legacy.py` 5 处，共 **42 处真实 Emoji**
  （🧭⚙️🎛🎯⚠️🔍🗂️📥📊📄🗑️🚀🧪🔗🔬✅❌🔁🔄📂🛠📚📭 等），分布在"文献证据/候选假设/研究计划/
  实验与运行/版本与反馈/设置"等工作区子页面复用的共享组件（`components.py`）以及回退控制台
  （`streamlit_app_legacy.py`）中；这些子页面在上一轮结构性重构中并未被逐一审查 Emoji 使用，
  是本轮通过硬指标复核才发现的真实缺口，不属于"已知已修复"，如实记录。
- 本轮修改：逐条替换为纯文本标题/按钮文案，或替换为几何符号（`◆` `×` `!` `•`）等不在 Emoji
  Unicode 区间内的中性状态符号，未改变任何按钮的 `key`、回调逻辑或可点击范围。
- 修改后：对 `app/ui` 全目录重新扫描，`TOTAL_TRUE_EMOJI=0`；随后重跑
  `pytest tests/test_scientific_ui_redesign.py tests/test_ui_localization_contract.py tests/test_ui_error_api_contract.py`
  （36 项全部通过）与浏览器实测导航（首页→工作区→科学问题/文献证据/候选假设/研究计划/
  实验与运行/版本与反馈/历史运行/结果与导出/知识库/设置，10 个子页面均正常渲染真实内容；
  设置页「高级选项→旧版控制台」按钮可点击并正确跳转至 `/legacy`），确认未引入回归。

## 四、总体结论

- 硬验收指标（第十一章）绝大多数项已满足，详见最终报告中的逐项取值；
- 3 项记录为"部分达标/未验证"而非编造为 100% 一致：**顶部栏高度略超**、**快速操作卡高度略低**、
  **侧栏折叠宽度未验证**；均为可测量的小幅偏差或已知自动化局限，已在差异分析中给出技术原因
  和可选修复方案，不影响功能完整性和硬性验收门槛；
- 首页内容宽度在超宽视口下与描述性目标存在数学互斥，本轮已选择更具体、更可验证的留白数值表
  作为优先满足对象，并在报告中完整披露权衡依据。
