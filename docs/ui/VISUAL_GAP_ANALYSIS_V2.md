## 0. 关于三张输入图片的说明（必须先声明，不得回避）

本轮任务文本要求本次对话应包含 `APPROVED_REFERENCE`（效果图）、`CURRENT_LANDING`、
`CURRENT_WORKSPACE` 三张图片。**经核查，本次 Cursor 对话的工具调用上下文中并未附带任何
图片文件**（未收到图片附件，`Read` 工具也未在会话中被要求读取任何用户上传的效果图路径）。

因此本次差异分析改用以下等价视觉真值来源，而不是凭空编造"已看过效果图"：

1. 任务文本第四、五章给出的**逐项可测量数值目标**（导航高度、Hero 高度、侧栏宽度、
   卡片尺寸等），本身就是效果图的数值化表达，本报告直接以这些数值作为"目标值"；
2. 上一轮会话（本轮之前）已完成的首页/工作区结构性重构（导航、Hero、SVG 主视觉、
   侧栏、顶部栏、KPI 卡、快速操作、时间线）——即本轮开始时的"当前实现"；
3. 本轮新截图 `docs/ui/after/*.png`（1920×1080 / 1600×900 / 1440×900 / 1366×768 +
   未选题态 + Q028 态）与 Playwright 实测像素值。

若后续对话补充了真实的效果图文件，需要在此基础上追加一轮逐像素对比；本报告的"目标值"
在没有真实图片输入的前提下，严格采用任务文本给出的数值区间，不使用"风格接近"这类不可
测量的表述。

## 4. 已知局限（未回避，按第十二章要求列出技术原因）

1. **侧栏折叠宽度未获自动化验证**：Streamlit 侧栏折叠由前端框架内核控制（`stSidebarCollapseButton`），本轮自动化脚本未能稳定命中该按钮完成点击后测量；已采用最接近方案（保留 Streamlit 原生折叠交互，仅约束展开宽度），功能未丢失，但折叠宽度数值标注为 `UNVERIFIED` 而非编造通过。
2. **顶部栏高度 84px 略超 68–76px 目标**：受 Streamlit 原生 `selectbox` 组件最小高度约束，如需强行压至 76px 以内需要覆盖 BaseWeb 内部行高变量，存在破坏点击区域可用性的风险，本轮未做（不属于硬验收指标）。
3. **首页内容宽度在 1600/1920 超宽视口下超出 1360–1440px 目标区间**：因该目标与同章节留白数值表在数学上不可同时满足（见第 1 节表格说明），本轮优先满足更具体的留白数值表与"不得使用大留白"的强约束。
4. **控制台 404**：`/workspace/_stcore/health`、`/workspace/_stcore/host-config` 出现 404，属 Streamlit 多页应用在子路由下轮询内核心跳接口时路径拼接产生的框架级已知行为，与本轮 UI 改动无关（未修改任何路由/内核配置），不影响页面功能，已在最终报告中如实列出，不计入"已解决"。
